## Reflection Questions

**Why not connect as the master user?**
The master user has unrestricted DDL privileges — it can drop tables, alter schemas, create users.
An application only needs DML (SELECT, INSERT, UPDATE, DELETE) on specific tables. Creating a
dedicated app user with least-privilege grants limits blast radius if credentials are stolen or
the app is compromised. The master user should only be used for admin operations.

**Why Secrets Manager over Parameter Store for the password?**
The password needs automatic rotation — Secrets Manager has native integration with RDS to rotate
the password on a schedule without downtime. Parameter Store standard tier has no built-in rotation
mechanism. Secrets Manager also encrypts at rest by default and supports fine-grained IAM `Resource`
scoping per secret. The per-secret cost (~$0.40/month) is justified for any credential that
rotates or requires auditing.
